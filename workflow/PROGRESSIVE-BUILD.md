# Progressive visual construction

Apply within shared FLOW stages 3, 4 and 6. These are internal work passes, not extra user questionnaires. The existing direction and refined-sample checkpoints remain. Complete representative samples before expanding the product; do not build the entire system on an unproven composition.

| Pass | Build and inspect | Exit evidence |
|---|---|---|
| 1. Composition | Shell, navigation, real content blocks, primary task, density, shared axes, anchors and scroll/fold. Work mostly in neutral tones with provisional readable type sizes. | Whole-viewport screenshot: the intended first focus and main task are understandable without decorative effects. |
| 2. Visual language | Typography, palette roles, color-area budget, shape and purposeful surfaces. Fit actual fonts and reflow the layout. Taste leads; keep each direction within the selected character. | Same viewport comparison: hierarchy and identity are stronger, with readable contrast and no broken wraps. |
| 3. Content and graphics | Realistic copy, coherent data, actual chart encodings, scales, legends, media and library icons. Choose graphics for a question, not for chart variety. | Native-scale inspection: values, labels and visual encodings agree; media is finished and the target task has an inferable route. |
| 4. Components and craft | Consolidate recurring sample controls, states, padding, optical alignment, stroke weights and entity containment. Use real content lengths from pass 1; do not postpone all data to pass 3. For a chart-led screen, sketch its encoding and information needs during composition, then finish its geometry in pass 3. Typography affects layout, so pass 2 may return to pass 1. This is focused iteration, not an irreversible waterfall. Spatial structure and naming start immediately; pass 4 is refinement, not permission to leave a flat tree.

For three candidate directions, settle their distinct compositions before expensive finishing. Finish both sample screens in each direction through passes 2–4 before checkpoint 1; users choose from convincing visual proposals, not unfinished wireframes. Do initial viewport/task sanity checks before showing them. Passes 5–7 are completed on the selected direction before checkpoint 2; motion remains proportional to the brief.

## Compare composition and execution before checkpoint 1

1. Start with the whole first viewport of each sample. Compare it with a relevant execution benchmark at a comparable viewing scale. Identify the content or visual element that best explains the product's main task, where the eye actually lands, and what competes with that element. Examine relative size, hierarchy and grouping. Look for a meaningful expression of the same direction on the companion screen.
2. Inspect a representative high-risk fragment from each direction at 100% scale. Pick a fragment that matters to the task, such as a chart with its key state, a dense table with its actions, or an inspection panel. Compare the relevant type, spacing, contrast and state cues with a strong example. For a detail panel or overlay, check what information or action it adds and whether its footprint suits that purpose.
3. Record 1–3 priority gaps for the correction round in the existing ROUNDS record, citing the frame/viewport and benchmark. Address composition or hierarchy first when it is the main gap, then compare the same view again. Keep a before/after pair for substantial changes. If a correction improves one screen, check what it does to the companion screen before presenting the pair.

This comparison belongs to the existing composition and craft passes. During refinement or expansion, repeat it where a change affects the focal hierarchy or introduces a new high-risk pattern.

Each correction round has one primary focus and 1–3 concrete gaps in docs/ROUNDS.md. Avoid changing layout, palette, typography and effects simultaneously during a polish round; a dependent fix is allowed and recorded. Capture before/after for meaningful decisions, not every node mutation. Check a representative screen before propagating source-component changes. If a change regresses the task or composition, revise or revert it rather than layering more effects over it.

## Redraw when the concept feels generic

At the existing visual reviews, identify the main decision and the visual element that makes it easier. Explain how that element expresses this product's subject or working method, and point to a related choice on the companion screen. A convincing motif can be a precise chart, a distinctive composition, a view of the subject or a well-designed interaction state. Judge how much it improves the task and whether the requested character is visible at first glance.

If the screen feels interchangeable or its most prominent area repeats information, treat that as a composition or visual-language finding. Preserve the current pair, then redraw the affected frame or dominant area on a working copy. For an unclear solution, test two small compositional alternatives with identical content. Compare before and after at the same viewport and at 100% for the changed area. Keep the stronger version and carry the change to the companion screen only after checking that it improves the journey. Use the existing correction rounds and checkpoints.

The designer chooses routine pass details and proceeds autonomously between existing checkpoints. No automatic browser implementation, animation code, extra screens or new design-file reset follows from this method.

## Carry quality through the passes

During composition, justify major card/dialog footprints and what each disclosure adds. During visual-language work, check the requested character through concrete composition/type/graphic decisions, not palette and radii alone. During graphics/content work, refine chart craft and edit redundant explanation without hiding essential interpretation. During component work, encode persistent layout rules under figcraft-file-craft and check real sources/instances. Keep these decisions in existing TARGET/DIRECTION/ROUNDS and polish records; do not create a new checklist document per pass.

Revisit the whole-screen identity after technical cleanup. If layout or copy changes flatten the selected direction, correct that regression within the same bounded iteration procedure. Structural validity, data accuracy and character fit are separate judgments; none certifies the others.
